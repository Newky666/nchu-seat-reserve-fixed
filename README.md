# 南昌航空大学图书馆座位自动预约

基于蓝航 App 的接口，实现图书馆座位的**自动预约**，图形界面可视化操作，零第三方依赖。

## 核心功能

- **图形界面**：选楼层 → 选阅览室 → 选座位 → 选时间段 → 一键预约
- **多学号（多账号）**：一个程序管理多个学号，各自预约信息互不干扰
- **习惯座位记忆**：记住每个学号常坐的座位，下次一键复用
- **预约次日（定时抢座）**：记录任务，每晚 22:00 放号后自动抢第二天的座位
- **即刻预约（今天）**：预约今天未过的时间段
- **预约记录 + 日志**：结果实时显示，退出自动清理

## 三、完整操作流程（首次使用，约 10 分钟）

### 第 1 步：抓包（拿个人认证信息）

预约接口需要你个人的 `auth` / `uid` 两个 Cookie（相当于"登录凭证"），必须抓包获取。

详细图文步骤见 **[README_抓包指引.md](./README_抓包指引.md)**，简版：

1. 小米平板装 **Reqable**（应用商店搜）
2. 开启抓包 → 微信/蓝航里进「座位预约」→ 提交一次预约
3. 停止抓包 → 找到带 `bookSeats` 的请求 → 导出 cURL（或 HAR）
4. 把文件发到电脑

### 第 2 步：导入认证信息（可导入多个学号）

- **图形界面**：点顶部「导入抓包文件」→ 选择文件
- **命令行**：

```powershell
py main.py --import 抓包文件.txt
```

程序自动提取 `auth`、`uid`、`seatBookers`、**学号**、**座位 id**，按学号分别保存。支持 cURL 和 HAR 两种格式。

> **多学号**：每个学号抓一次包、各导入一次，之后在顶部「用户ID」下拉切换。

### 第 3 步：选座位

1. **楼层**：下拉选择
2. **阅览室**：下拉选择（标注 `[室内·房间]` / `[室外·过道]`，自习区 = 过道）
3. **座位号**：自己填写（如 `211`）

> **习惯座位**：预约成功后，座位号 + 房间 + 楼层自动记入 `bookmemory.json`。下次切到这个学号时，「习惯座位」下拉显示历史座位（最多 5 个，最新在前），点一下自动填充楼层/阅览室/座位号。

### 第 4 步：选时间段

选开始时间 + 结束时间 → 点「添加时间段」。可添加多个，单段 1~6 小时（超长自动拆分）。

### 第 5 步：预约

| 按钮 | 说明 |
| --- | --- |
| **预约次日(到22:00自动抢)** | 记录任务，等到 22:00 放号后**自动抢明天的座位** |
| **即刻预约(今天)** | 预约**今天**已添加的时间段（开始时间早于当前整点的自动跳过） |

预约结果实时显示在「本次预约记录」和底部日志。

## 四、预约方式详解

### 预约次日（定时抢座）

点击后**不会立即预约**，而是：

1. 记录任务（学号、座位、时间段）
2. 后台等待到放号时间（默认每晚 **22:00**）
3. 到点**自动执行预约**
4. 结果写到底部日志

```
[定时预约] 已记录: 明天 40座 21:00-22:00, 将在 22:00:00 放号后自动抢
...（到点自动抢）
[预约成功] 40座 21:00-22:00 (bookingId=xxx)
```

> 注意：定时等待期间**程序需保持运行**（不要关窗口）。如果点击时已经过了 22:00，会立即预约。

### 即刻预约（今天）

预约今天已添加的时间段。**时间校验向前取整到整点**：

> 现在是 **7:03**，向前取整到 **7:00**，所以 **7:00 及以后**的时间段都可预约；早于 7:00 的会被自动跳过。

例如现在 15:20：`14:00-18:00` 会被跳过（开始时间早于 15:00），`16:00-18:00` 可预约。

## 五、多学号（多账号）管理

- 顶部「**用户ID**」下拉列出所有已导入的学号，切换后各自的座位、时间段**互不干扰**（各自独立保存）。
- 「**清除预约信息**」：清空当前学号的座位/时间段/记忆的楼层（认证数据保留）。
- 「**清除抓包数据**」：彻底删除当前学号的 `auth`/`uid` 等登录凭证（**保护隐私**），预约信息保留；清除后需重新抓包导入才能预约。

---

## 六、预约记录与日志

### 预约记录（本次会话）

界面中部「本次预约记录」表格，列：**学号、座位、区域、预约时间、状态、操作时间**。

- 同一任务（学号+座位+时间段）只显示一行，状态在「成功 / 失败:原因 / 已取消」间更新
- 预约成功时记录系统时间
- 「取消选中」可取消已成功的预约

### 日志（底部深色控制台）

所有结果直接写到底部日志，例如：

```
[预约成功] 40座 21:00-22:00 (bookingId=xxx)
[预约失败] 40座 21:00-22:00 原因: 该座位已被他人预约
[已取消] 学号2404xxxx 40座 21:00-22:00
```

> **预约记录和日志都在程序退出后自动清理**（不写入文件）。

## 八、配置文件与记忆文件

### `config.json`（自动生成/更新）

> **首次使用**：仓库出于隐私考虑**不包含** `config.json`（内含登录凭证 auth/uid）。请先复制模板并改名，再运行程序：
>
> ```powershell
> copy config.example.json config.json
> ```

```jsonc
{
  "accounts": {
    "2404xxxx": {                        // 学号
      "student_id": "2404xxxx",
      "auth": "...", "uid": "...",       // 登录凭证(抓包导入)
      "seat_bookers": ["289306"],        // 预约人ID
      "reserve": { "target_seats": ["61078"], "preferences": {...} },
      "tasks": [],
      "gui_state": { "seat_num": "40", "time_segs": [["21:00","22:00"]] }
    }
  },
  "schedule": { "release_time": "22:00:00", "open_time": "08:00", "close_time": "22:00" },
  "current": "2404xxxx"                  // 当前选中的学号
}
```

### `bookmemory.json`（习惯座位记忆）

按学号记录历史预约座位，**只存座位号 + 房间 + 楼层**（不存时间段），每学号最多 5 条，超出自动用最新替换最旧。

```jsonc
{
  "2404xxxx": [
    {"seat_num": "40", "room": "社会科学阅览室一（201）", "floor_name": "图书馆二楼", "content_id": "87"}
  ]
}
```

> 习惯记忆**持久化保留**，不会随程序退出清除；如需清理，手动删除该文件即可。

## 九、登录失效处理（重要）

`auth` / `uid` 会**过期失效**（时间不定，可能几天）。失效后预约报错，日志会提示「登录已失效」。

**处理**：重新抓包（第 1 步）→ 重新导入（第 2 步），约 2 分钟。配置、座位、记忆都不会丢。

## 十、常见问题

**Q：预约提示 `SeatTimeRangeOut`？**
A：正常，说明还没到放号时间（每晚 22:00 才开放第二天的座位）。用「预约次日」定时抢，或 22:00 后再试。

**Q：插座是怎么分布的？**
A：程序内置学校最新规则：
1. **自习区**（各层过道）→ 每个座位都有插座
2. **二楼社科阅览室一（201）**→ 每个座位都有插座
3. **一站式学生社区** → 每个座位都有插座
4. **其他阅览室** → 固定区域才有

**Q：能预约多个时间段吗？**
A：能。点「添加时间段」可多次添加，单段 1~6 小时。

**Q：预约记录和日志为什么退出就没了？**
A：设计如此。它们只记录本次运行期间的操作，退出自动清理，不写任何文件（习惯记忆除外）。

**Q：会不会伤硬盘/被封号？**
A：只在预约时发几次请求，频率极低，和手动操作一样，无风险。
